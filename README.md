## 🚀 Project Overview

The **Student Portfolio & Academic Management Website** is a responsive, multi-page web application developed to showcase my academic journey, technical skills, personal projects, and development experience as a Software Engineering student at Miva Open University.

The project was developed as part of **COS 106 – Introduction to Web Technologies**, with the objective of applying fundamental web development concepts to a practical, interactive website.

Unlike a traditional static portfolio, this application integrates an **Academic Task Planner**, allowing students to organize assignments, manage deadlines, track completed tasks, and monitor academic productivity.

The website combines personal branding, academic documentation, project presentation, and productivity features within a consistent user interface.

It was developed using **HTML5, CSS3, and vanilla JavaScript**, without requiring a frontend framework, backend server, or external database.

### What Makes This Project Different?

The application demonstrates how foundational web technologies can be used to create an engaging and functional platform.

It combines:

- A professional personal portfolio.
- An organized academic profile.
- An interactive project showcase.
- An academic task management system.
- Browser-based persistent task storage.
- A weekly lecture timetable.
- Responsive layouts and interactive animations.
- A validated contact form.
- Multimedia integration.
- Light and dark theme support.

The project emphasizes clean code organization, usability, responsive design, and practical JavaScript functionality.

## 📋 How the Academic Planner Works

The Academic Planner is one of the main interactive features of the application.

It uses JavaScript to manage an array of task objects and dynamically render their content.

### Step 1: Create a Task

Navigate to the Academic Planner page.

Enter:

- Task description.
- Associated course.
- Due date.
- Priority level.

Click **Add Task**.

JavaScript validates the form and inserts the task into the task collection.

### Step 2: View Tasks

Tasks are dynamically displayed with their associated information.

Each task includes:

- Description.
- Course.
- Due date.
- Priority.
- Completion status.

### Step 3: Complete a Task

Select the checkbox beside a task.

The planner updates its completion status and recalculates progress statistics.

### Step 4: Filter and Search

Users can filter tasks using three views:

- All
- Pending
- Completed

The search field allows users to find tasks by their titles or associated courses.

### Step 5: Delete Tasks

Individual tasks can be removed using the delete button.

Users can also clear all completed tasks after confirmation.

### Step 6: Track Progress

The application automatically recalculates progress whenever tasks are added, completed, or removed.

The completion percentage is calculated as:

```text
Completion Percentage =
(Completed Tasks / Total Tasks) × 100
```

When there are no tasks, progress is displayed as 0%.

### Step 7: Preserve Tasks

Tasks are saved to browser localStorage.

They remain available after refreshing the page or reopening the website in the same browser profile, provided the stored data has not been cleared.

## 💾 Data Storage

The Academic Planner uses the browser's localStorage API to preserve task data.

### Storage Key

```javascript
const STORAGE_KEY = "academicPlannerTasks";
```

### Saving Tasks

```javascript
localStorage.setItem(
  STORAGE_KEY,
  JSON.stringify(tasks)
);
```

### Loading Tasks

```javascript
const savedTasks = localStorage.getItem(STORAGE_KEY);
```

When saved data is available, the planner parses it into JavaScript objects.

When no saved data exists, the application initializes a small set of sample tasks.

### Benefits

- No database configuration is required.
- Tasks can persist across page reloads.
- Data can be accessed without a backend.
- The implementation is lightweight.
- The website remains suitable for static hosting.

### Storage Limitations

localStorage is browser-specific.

Therefore:

- Tasks do not automatically synchronize across devices.
- Data may be lost when browser storage is cleared.
- Private browsing sessions may not retain data.
- Users cannot currently access their tasks through an account on another device.

For a future production version, a database and user authentication system could be introduced.

## ✅ Form Validation

The Contact page uses JavaScript to validate user input before displaying a simulated submission confirmation.

### Validation Rules

**Full Name**

- Required field.
- Minimum of two characters.

**Email Address**

- Required field.
- Must match a valid email format.

**Phone Number**

- Required field.
- Must contain digits only.
- Must contain between 7 and 15 digits.

**Message**

- Required field.
- Minimum of 10 characters.
- The form interface supports a 500-character message limit.

### Validation Feedback

The form provides:

- Field-specific error messages.
- Visual indicators for valid and invalid fields.
- Validation when leaving an input.
- Additional validation during editing.
- Focus on the first invalid field.
- A live message character counter.

### Current Submission Behavior

The implementation demonstrates the user experience of submitting a form but does not connect to an email delivery service.

To enable real message delivery, a backend or form-handling service would need to be integrated.

## ⚠️ Limitations

The current version is intended as an educational project and a personal portfolio.

Known limitations include:

1. The Academic Planner stores tasks locally in the browser rather than in a centralized database.
2. There is no user authentication or account synchronization.
3. The contact form simulates successful submission and does not deliver emails.
4. The weekly lecture timetable is presented as static content.
5. Some media assets and font resources depend on an internet connection.
6. No automated test suite is documented in the current repository.

These limitations provide opportunities for future development.
